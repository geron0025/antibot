# Канал предложений: что облако предлагает, а решает владелец

Версия формата: **1**.

> В нынешней сборке нода предложений не загружает и не принимает: ни
> кнопки в админке, ни каталога `proposals/` пока нет. Формат
> зафиксирован заранее, как и формат агрегата.

Третья дорога между частями. Первые две — [агрегат](aggregate.md) наверх и
[набор фактов](fact-set.md) вниз — переносят наблюдения и утверждения
о мире. Эта переносит **черновик правила**: облако разобрало статистику
одного подписчика и предлагает ему правило, которое он может принять
одной кнопкой в своей админке.

## Граница, которая не сдвигается

**Предложение — это черновик, а не команда.** Оно не может ничего
включить, заблокировать или изменить само по себе. Между предложением и
работающим правилом стоит человек, и убрать его оттуда нельзя ни
настройкой, ни ответом облака.

Устроено это тремя ограничениями, каждое из которых проверяется на ноде:

1. **Предложение не содержит режима.** Поля `mode` в нём нет вовсе — не
   «оно должно быть `shadow`», а его нельзя выразить. Принятое
   предложение нода записывает в `shadow` всегда, потому что другого
   значения ей взять неоткуда.
2. **Принятие поштучное.** Кнопки «принять всё» нет ни в админке, ни в
   командной строке, ни в конфиге. Настройки «принимать автоматически»
   не существует, и её появление означало бы отмену этого документа.
3. **Идентификаторы разделены.** `id` предложенного правила обязан
   начинаться с `cloud-`; правило, сочинённое владельцем, такой префикс
   не носит. В `antibot rules list` видно, что откуда взялось.

Причина не в осторожности, а в арифметике: одно ошибочное правило,
разошедшееся по всем установкам, — это одновременный отказ у всех
клиентов сразу и конец сервиса. Возможности сделать так не должно
существовать в коде.

## Чем это отличается от набора фактов

| | Набор фактов | Предложение |
|---|---|---|
| Кому | всем одинаковый | одному подписчику |
| Что переносит | утверждения о мире | черновик правила |
| Подпись | ключ раздачи | **отдельный ключ** |
| Применение | автоматическое, после проверок | только руками владельца |
| Если не применилось | база устаревает | ничего не происходит |

Разные ключи — не педантизм. Набор фактов подписывается ключом, который
раздаёт одно и то же всем; предложение адресное. Один ключ на оба канала
означал бы, что компрометация подписи предложений позволяет подделать
базу для всех сразу.

Обратное тоже верно и стоит сказать вслух: **компрометация ключа
предложений ограничена по последствиям**. Подделанное предложение всё
равно приедет черновиком, ляжет в `shadow` и не начнёт ничего резать,
пока человек не нажмёт кнопку и не посмотрит, что она резала бы.

## Предложение целиком

```json
{
  "format": 1,
  "node": "8f14e45fceea167a5a36dedd4bea2543",
  "created_at": "2026-09-09T04:00:00Z",
  "proposals": [
    {
      "id": "cloud-hosting-no-browser-2026-09",
      "created_at": "2026-09-09T04:00:00Z",
      "expires_at": "2026-10-09T00:00:00Z",
      "requires_facts_version": 137,
      "rule": {
        "id": "cloud-hosting-no-browser-2026-09",
        "name": "хостинг без браузерного рукопожатия",
        "scope": ["shop.example.ru"],
        "priority": 100,
        "condition": {
          "all": [
            {"field": "network.class", "op": "eq", "value": "hosting"},
            {"field": "ua_matches_ja4", "op": "eq", "value": false},
            {"field": "network.age", "op": "gt", "value": 3}
          ]
        },
        "action": {"type": "block", "status": 403}
      },
      "why": "За неделю 4128 запросов с шести сетей класса hosting, назвавшихся Chrome, с отпечатком TLS библиотеки Go. Ни одного запроса к robots.txt.",
      "evidence": {
        "window": "2026-09-02/2026-09-09",
        "requests": 4128,
        "share": 0.021,
        "networks": 6,
        "addresses": 143,
        "would_block": 4128,
        "would_block_protected": 0
      }
    }
  ]
}
```

### Поля предложения

| Поле | Что |
|---|---|
| `id` | с префиксом `cloud-`; повтор того же `id` — обновление предложения |
| `expires_at` | после этой даты нода прячет предложение |
| `requires_facts_version` | правило ссылается на факты; с более старым набором оно не сработает |
| `rule` | правило в формате `rules.json`, **без** `mode` и `enabled` |
| `why` | одна фраза человеку: почему это предложено |
| `evidence` | числа из **его собственной** статистики |

`evidence` обязателен и обязан быть проверяемым на месте. Владелец,
получивший «мы предлагаем запретить, поверьте нам», не нажмёт кнопку —
и правильно сделает. Поэтому рядом с предложением едут числа, которые он
может воспроизвести сам: `antibot replay` по своему же журналу должен
дать те же значения.

Из них главное — `would_block_protected`: сколько запросов правило
срезало бы у сетей с пометкой «не трогать». Ненулевое значение — повод не
предлагать вовсе, а не примечание мелким шрифтом.

`share` — доля от всех запросов за окно. Правило, задевающее заметную
долю трафика, почти наверняка задевает и людей: столько трафика ботовым
не бывает.

## Раздача

```
GET <facts.url>/proposals?format=1
Authorization: Bearer <токен>
```

Тот же токен, что у агрегатов и набора фактов. **Отдельной области
токена у предложений нет**: `facts` (или `both`) покрывает и базы, и
предложения — это одно направление, сверху вниз, и делить его дальше
значило бы заводить сущность ради симметрии. Доступ решает **уровень
подписки**: предложения полагаются уровню `facts_and_analysis`.

| Ответ | Что делает нода |
|---|---|
| `200` | разбирает, проверяет подпись, складывает к себе |
| `304` | ничего |
| `401` | токен не годится: показывает прежние предложения, повтор через час |
| `403` | уровень подписки не тот: прежние предложения остаются, повтор раз в сутки |
| `429`, `5xx` | повтор с ростом задержки |

Подпись — в заголовках ответа, над **байтами тела** как они пришли:

```
X-Antibot-Signature: 2026-p1:MEUCIQ…
```

До двоеточия — `key_id`, после — Ed25519 над `sha256` тела. Подпись над
байтами, а не над разобранным документом, избавляет обе стороны от
канонизации JSON: подписывается ровно то, что отправлено.

Ключи предложений живут в том же файле `facts/keys.json` и по тем же
правилам ротации, но помечены `use: "proposals"`. Ключ раздачи для
предложений не годится и наоборот — назначение проверяется до подписи.

## Что делает нода

Проверки по порядку; любая непройденная означает «оставить прежние
предложения и написать в лог»:

1. подпись сходится с ключом из списка **предложений**;
2. `node` в теле совпадает с идентификатором этой ноды — иначе это
   чужие предложения, и принимать их нельзя;
3. документ прошёл проверку по схеме;
4. у каждого правила `id` начинается с `cloud-`;
5. `scope` каждого правила — домен, который эта нода обслуживает, или
   `*`.

Прошедшие проверку складываются в `proposals/` рядом с `facts/`.
Приезжает список целиком: предложение, пропавшее из списка, нода
скрывает — облако передумало.

### Принятие

Владелец нажимает кнопку в админке. Нода:

1. дописывает правило в `rules.json` с `mode: "shadow"` и включённым
   состоянием;
2. идёт тем же путём записи, что и `antibot rules`: та же проверка
   набора, та же атомарная замена, та же запись в журнал ноды — кто и
   что принял;
3. помечает предложение принятым, чтобы не предлагать повторно.

Дальше правило живёт как любое другое: владелец смотрит на него в
`shadow`, прогоняет `antibot replay` и **сам** переводит в `active` —
кнопкой на странице правил или командой `antibot rules mode`; нода
применяет это без перезапуска. Перевод в `active` — не часть этого
канала.

### Отказ

Отклонённое предложение нода прячет и запоминает отказ у себя. Наверх об
этом не сообщается: канала снизу вверх, кроме агрегата, в протоколе нет,
и заводить его ради «пользователь нажал нет» — плохой размен. Облако
продолжит присылать предложение, пока считает его уместным; на ноде оно
видно не будет.

## Чего в этом канале нет

- **Нет способа включить правило.** `mode` не выражается форматом.
- **Нет способа изменить чужое правило.** Предложение только добавляет
  новое, с собственным префиксом `id`; правила владельца оно не трогает.
- **Нет способа изменить настройки ноды.** Ни адресов, ни сетей, ни
  портов, ни своих сетей — в формате нет полей для этого.
- **Нет автоматического принятия.** Ни ответом облака, ни настройкой.

Если однажды понадобится что-то из перечисленного — это новый документ и
новый разговор, а не поле в этом формате.

## Схема

Машиночитаемая схема — [../../schema/proposals.schema.json](../../schema/proposals.schema.json).
Нода проверяет документ по схеме до того, как показать хоть одно
предложение человеку. Предложение, не прошедшее проверку, отбрасывает
**весь** список: частично разобранный список — это состояние, которого
никто не проверял.
