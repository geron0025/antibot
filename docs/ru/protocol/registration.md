# Регистрация ноды: как нода получает токен

Версия формата: **1**.

Этот документ, как остальные в этой папке, зафиксирован до кода и лежит
в открытой части намеренно: регистрация — единственный запрос, который
нода делает **до** того, как у неё появился токен, и любой должен видеть,
что в нём уходит.

## Зачем это есть

Токен нужен обеим стрелкам провода: без него нода не получает наборы
фактов и не отправляет агрегаты. Пока токен выдавался человеком, путь
клиента упирался в переписку с нами — а мерка этапа 1 звучит «поставил
сам, без нашей помощи». Регистрация убирает переписку: нода
представляется облаку и получает токен бесплатного уровня.

**Регистрация ничего не включает.** Она добывает токен, и только. Что с
ним делать — решают галки владельца в админке ноды; пока он их не
поставил, нода никуда ничего не отправляет и ничего не скачивает. Токен
сам по себе не меняет ни одного байта в поведении ноды.

## Запрос

```
POST /register
Content-Type: application/json
```

Без заголовка `Authorization`: токена ещё нет, в этом весь смысл.

```json
{
  "format": 1,
  "node": "01JB8Z0K4W9Q7N2M5T6X8YV3PR",
  "version": "v0.6.0",
  "facts": true,
  "aggregates": false
}
```

| Поле | Тип | Что |
|---|---|---|
| `format` | целое | версия формата, сейчас `1` |
| `node` | строка | идентификатор установки — тот же, что в агрегате |
| `version` | строка | версия ноды, как её печатает `antibot version` |
| `facts` | булево | владелец отметил «получать обновления безопасности» |
| `aggregates` | булево | владелец отметил «отправлять статистику» |

Поля `facts` и `aggregates` ни к чему не обязывают и ничего не
ограничивают: токен выдаётся с областью `both` в любом случае. Они
отвечают на вопрос, за чем пришли, — это единственная возможность
узнать, чего люди на самом деле хотят от облака, и она стоит одного
булева поля.

Оба `false` — допустимый запрос: владелец мог снять обе галки и всё
равно завести учётку на будущее.

## Чего в запросе нет

| Не отправляется | Почему |
|---|---|
| Домены под защитой | облако узнаёт их из агрегатов, и только если владелец включил отправку |
| Почта и имя владельца | регистрация не заводит переписку; связь — из админки облака, если владелец сам её оставит |
| Правила и их тексты | не уходят никогда и ни в каком запросе |
| Адреса посетителей | здесь их нет по определению |

Облако видит **адрес, с которого пришёл запрос** — это адрес сервера
самого владельца, не его посетителей. Он записывается: без него предел
на число регистраций с одного места не построить. Записанный адрес виден
в админке облака и больше нигде.

## Ответ

`201 Created`:

```json
{
  "format": 1,
  "token": "ab_2f9c1d8e7b6a5c4d3e2f1a0b",
  "scope": "both",
  "level": "node",
  "tenant": "node-01JB8Z0K",
  "facts_url": "https://updates.netbota.ru/facts",
  "ingest_url": "https://updates.netbota.ru/ingest"
}
```

| Поле | Что |
|---|---|
| `token` | значение токена; **показывается один раз**, облако хранит только хеш |
| `scope` | область токена: `both` — годится и для наборов, и для агрегатов |
| `level` | уровень подписки: `node` — бесплатный |
| `tenant` | как называется заведённый арендатор; нужно, чтобы владелец мог назвать себя, когда пишет нам |
| `facts_url` | откуда забирать наборы фактов |
| `ingest_url` | куда отправлять агрегаты |

Адреса приходят в ответе, а не зашиты в ноду, по той же причине, по
которой набор фактов версионируется: переезд сервиса не должен требовать
выпуска ноды. Если в конфиге ноды адреса заданы руками, побеждает конфиг:
у владельца всегда остаётся последнее слово о том, куда ходит его нода.

Токен потерян — новый по этому же пути не выдаётся, см. `409` ниже.
Поэтому нода записывает его сразу и до того, как ответит владельцу, что
всё получилось.

## Что даёт бесплатный уровень

Уровень `node` получает **только бесплатный поток** — роботов из списков,
которые их владельцы публикуют о себе: Google, Bing, Apple, Yandex и
прочие ([fact-set.md, «Два потока»](fact-set.md#два-потока)). Классы
сетей, `protected` операторов связи, пулы прокси и отпечатки — за
подпиской.

Агрегаты от бесплатного арендатора облако принимает. На каталог они при
этом не влияют, пока человек не подтвердит арендатора: иначе самозапись
была бы способом переписать каталог для всех — одной командой завести
сотню нод и рассказать облаку, что сеть фермы принадлежит оператору
связи.

## Отказы

| Код | Когда | Что делает нода |
|---|---|---|
| `400` | тело не разбирается, нет `node`, `format` не тот | показывает владельцу текст ошибки; повтор бессмысленен |
| `409` | эта установка уже зарегистрирована | говорит владельцу: токен уже выдавался, нужен новый — напишите нам |
| `429` | с этого адреса за сутки зарегистрировались слишком много раз | ждёт `Retry-After` и предлагает повторить позже |
| `503` | облако не в состоянии ответить | предлагает повторить; галки при этом не теряются |

Тело отказа — как у прочих ручек облака:

```json
{"error": "this installation is already registered"}
```

`409`, а не новый токен, — потому что облако хранит только хеш и
повторно показать прежний токен не может, а выдать второй значило бы,
что любой, кто знает чужой `node`, заводит себе токен от чужого имени.
Установка, потерявшая токен, — случай для человека, и он редкий.

## Повторная регистрация и переустановка

Идентификатор установки живёт в файле рядом с состоянием ноды. Снесли
ноду вместе с состоянием — новый идентификатор, и регистрация пройдёт
как первая: это новая установка, и для облака она неотличима от новой.
Арендатор при этом остаётся прежним только в одном случае — если
владелец сам перенёс файл с токеном.

Предел на число регистраций с одного адреса выбран так, чтобы не мешать
честному случаю «поднял, снёс, поднял заново»: пять в сутки.
