# Эксплуатация

## События

По строке на запрос, NDJSON. Формат выбран за то, что его читает всё:
`grep`, `jq`, любой скрипт и сам `antibot`, когда прогоняет правило по
истории.

```json
{"t":"2026-09-09T12:00:00Z","ip":"203.0.113.7","host":"shop.example.ru",
 "method":"GET","path":"/catalog","proto":"HTTP/2.0","ua":"curl/8.7.1",
 "ja4":"t13i4906h2_0d8feac7bc37_7395dae3b2f3","sni":"shop.example.ru",
 "alpn":"h2,http/1.1","tls":"1.3","h2":"1:65536;2:0|15663105|0|m,s,a,p",
 "hdrs":"accept,user-agent","hdrs_hash":"e5a56608905c6682",
 "net_class":"hosting","net_owner":"Example Hosting Ltd","net_age":7,
 "ua_ok":false,"decision":"block","rule":"block-hosting",
 "shadow":["watch-curl"],"status":403,"dur":47834}
```

| Поле | Что |
|---|---|
| `t`, `ip`, `host`, `method`, `path`, `proto` | запрос |
| `ua`, `ref` | заголовки |
| `ja3`, `ja3_hash`, `ja4`, `sni`, `alpn`, `tls`, `grease` | TLS |
| `h2` | отпечаток HTTP/2 |
| `hdrs`, `hdrs_hash` | состав заголовков |
| `family`, `ua_ok`, `net_*` | из набора фактов |
| `decision` | `pass`, `allow`, `block`, `ratelimit` |
| `rule` | какое правило решило |
| `shadow` | какие наблюдатели сработали |
| `status`, `bytes`, `dur` | ответ; `dur` в наносекундах |

Пустые поля не пишутся. Событие с `decision: "pass"` и без `rule` —
запрос, под который ничего не нашлось.

### Ротация

Файл на сутки, `events-2026-09-09.ndjson`; доросший до `max_size`
закрывается, и записи идут в следующий с номером. Уборка раз в час
удаляет файлы старше `keep_days`.

Смена суток закрывает файл специально: так уборка по сроку работает с
целыми файлами и не режет их изнутри.

### Полезное

```bash
# кого не пропустили за сегодня
jq -r 'select(.decision=="block") | .ip' events-$(date +%F).ndjson | sort | uniq -c | sort -rn

# один отпечаток на скольких адресах — это и есть вопрос «бот или люди»
jq -r 'select(.ja4!=null) | "\(.ja4) \(.ip)"' events-*.ndjson | sort -u | cut -d' ' -f1 | uniq -c | sort -rn

# что сработало в тени
jq -r '.shadow[]?' events-*.ndjson | sort | uniq -c
```

## Служебный порт

```bash
curl http://127.0.0.1:8091/healthz    # alive
curl http://127.0.0.1:8091/stats      # {"events_dropped":0,"version":"0.1.0"}
```

`events_dropped` обязано быть видно: журнал, теряющий события молча, хуже
отсутствующего, потому что по нему делают выводы. Растёт — увеличьте
`events.queue` или разберитесь, почему диск не успевает.

Наружу порт не публикуется.

## Что писать в мониторинг

- `/healthz` — живость;
- `events_dropped` из `/stats` — не растёт ли;
- доля `decision: "block"` — резкий рост означает либо налёт, либо
  правило, задевшее людей;
- дата в `antibot facts status` — не замерзла ли база.

Метрик в формате Prometheus нет: пока не попросит живая установка.

## Разбор поломок

### Сайт перестал открываться

```bash
antibot rules list                       # что действует
antibot replay -for 1h -examples 5       # кого режет прямо сейчас
```

Правило, задевающее больше процента запросов, почти наверняка задевает и
людей. Выключить — кнопкой в админке или `antibot rules disable ID`;
изменение подхватывается без перезапуска.

Если сломалось после обновления базы — `antibot facts rollback`. Сети для
этого не нужно.

### Правила не применяются после правки

Смонтирован **файл**, а не каталог. Замена идёт через `rename`, а
bind-mount одиночного файла в Linux привязан к иноду: новый файл — другой
инод, и контейнер до перезапуска применяет старые правила, ничем этого не
показывая.

Монтировать `/var/lib/antibot` целиком. На Docker Desktop подхватывается,
то есть на машине разработчика грабля не воспроизводится.

### Все запросы получают 403

Скорее всего правило вида `{"field": "ua_matches_ja4", "op": "eq",
"value": false}` на ноде **без баз фактов**. Проверьте
`antibot facts status`. Начиная с этой версии умолчание поля — `true`, и
такое правило не совпадёт ни с кем, но правило из более старой заготовки
могло рассчитывать на обратное.

### Браузер ругается на сертификат

Работает самоподписанный: `certificates_dir` не задан или в нём нет
подходящей пары. При старте это пишется предупреждением.

### Нода не поднимается

Проверка настроек идёт **до** занятия портов, поэтому причина всегда в
первой же строке журнала. Чаще всего:

| Сообщение | Что делать |
|---|---|
| `admin UI on … without a certificate` | задать `certificate`/`key` или слушать loopback |
| `admin_ui.enabled without admin_ui.listen` | задать адрес |
| `cloud.token is set and cloud.url is not` | или убрать токен, или задать адрес |
| `no listener is configured` | задать `listen.http` или `listen.https` |
| `is not a network like 10.0.0.0/8` | в `trusted_proxies`/`own_networks` адрес вместо сети |

### Отпечатки не снимаются

По HTTP их нет и быть не может: `ja4` и `h2` берутся из рукопожатия TLS и
фреймов HTTP/2. По HTTP/1.1 поверх TLS будет `ja4`, но не `h2`.

Состав заголовков по HTTP/1.1 снимается **без порядка**: восстановить его
можно только из сырых байт, которых `net/http` не сохраняет. Для HTTP/2
порядок известен точно, и там отпечаток сильнее.

## Обновление ноды

Состояние — файлы в `/var/lib/antibot`, они переживают замену бинарника и
образа. Правила, учётки, наборы фактов и события останутся на месте.

```bash
docker pull ghcr.io/geron0025/antibot:latest
docker restart antibot
```

Перезапуск разлогинивает всех в админке (сессии живут в памяти) и
обнуляет счётчики ограничителя частоты. Это осознанно.

## Резервная копия

```bash
tar czf antibot-$(date +%F).tar.gz \
  /etc/antibot/config.yaml \
  /var/lib/antibot/rules.json \
  /var/lib/antibot/admin.json
```

События в копию обычно не нужны — их много и они устаревают. Наборы
фактов тоже: они приезжают заново.

**В `admin.json` хеши паролей, в `certs/` приватные ключи.** Копия
должна лежать там же, где вы держите остальные секреты, а не в общем
файловом шаре.
