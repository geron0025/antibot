# antibot

Обратный прокси на Go, который снимает сетевой отпечаток клиента и по
нему отличает браузер от автоматизированного клиента. Один бинарник,
никаких внешних зависимостей: ни базы, ни кеша, ни очереди.

> Главная английская страница — корневой [README.md](../../README.md);
> остальное английское дерево — [../en/](../en/).

## Зачем

Заголовок `User-Agent` подделывается одной строкой. То, как клиент
устанавливает TLS-соединение и как открывает поток HTTP/2, — нет: это
определяется его библиотекой, и подделка требует переписать её.

Поэтому с каждого запроса снимается:

| Признак | Откуда |
|---|---|
| `JA3`, `JA4` | разбор ClientHello до передачи в `crypto/tls` |
| Отпечаток HTTP/2 (формат Akamai) | служебные фреймы SETTINGS, WINDOW_UPDATE, PRIORITY и порядок псевдо-заголовков |
| Состав заголовков и его хеш | какие заголовки пришли и в каком порядке |
| Рассогласование User-Agent и JA4 | клиент назвался Chrome, а рукопожатие не Chrome |
| Наличие GREASE | браузеры его шлют, самописные клиенты обычно нет |

Стандартной библиотекой это не снять: в `tls.ClientHelloInfo` нет списка
расширений и их порядка — а это половина JA3 и ключевая часть JA4, — и Go
молча отбрасывает GREASE-значения, хотя их наличие само по себе сигнал.

## Быстрый старт

```bash
docker run -d --name antibot \
  -p 80:8080 -p 443:8443 \
  -v /etc/antibot:/etc/antibot:ro \
  -v antibot-state:/var/lib/antibot \
  ghcr.io/geron0025/antibot:latest
```

Минимальный `/etc/antibot/config.yaml`:

```yaml
upstreams:
  - host: "*"
    to: "http://127.0.0.1:3000"
```

Всё остальное берётся из умолчаний. Нода поднимется, начнёт проксировать
и писать события — **не блокируя никого**: правил нет, значит и запретов
нет. Дальше — [установка](install.md) и [настройка](configuration.md).

## Что уже работает

- **разбор ClientHello** своими силами, `JA3` и `JA4` — сверены с
  эталонами Chrome, Firefox, Safari, curl, python и Go, плюс
  дифференциальный фаззер против `crypto/tls`;
- **отпечаток HTTP/2**: SETTINGS, WINDOW_UPDATE, PRIORITY и порядок
  псевдо-заголовков. Тот же запрос от Go даёт `a,m,p,s`, от curl —
  `m,s,a,p`, от Chrome — `m,a,s,p`;
- **отпечаток по составу заголовков**;
- **проксирование** с маршрутами по имени хоста, настоящим адресом
  клиента и выбором сертификата по SNI, включая самоподписанный запасной;
- **события в NDJSON** с ротацией и сроком хранения;
- **слой своих сетей**, который проверяется раньше правил;
- **правила**: условие по фактам, области, режимы `shadow` и `active`,
  действия `block`, `allow` и `ratelimit`; файл перечитывается на лету;
- **прогон по истории** — тем же матчером, что и горячий путь;
- **ограничитель частоты** — скользящее окно в памяти процесса;
- **админка**: события, статистика и правила;
- **базы фактов**: разбор, подпись, применение с диска, загрузка по
  сети, откат;
- **отправка агрегатов** в облако — только с токеном подписки;
  `antibot aggregate show` показывает ровно то, что уйдёт.

Нет: ACME, метрик в формате Prometheus.

Проверено: контейнер поднимается в сети **без доступа наружу**, с пустым
каталогом баз, и обслуживает HTTPS и HTTP. Ни одной базы данных при этом
не запущено — иначе ноду не поставят.

## Устройство

```
клиент ──TLS/HTTP2──► antibot ──HTTP/1.1──► ваш сайт
                         │
                         ├──► events/*.ndjson   события, ротация по сроку
                         ├──◄─ rules.json       правила, перечитываются на лету
                         └──◄─ facts/*.json     базы сетей и отпечатков
```

Всё состояние — файлы на диске. Правила и факты держатся в памяти
скомпилированными и перечитываются без перезапуска; горячий путь запроса
не ходит ни в какое хранилище и не может в нём застрять.

## Границы, заданные с первого дня

- **Ничего не отправляется без токена.** Не «телеметрия выключена
  настройкой», а отсутствие адресата: пока в конфиге нет токена, код
  отправки не выполняется вовсе.
- **Приходящие базы ничего не блокируют.** Они меняют только то, как
  называется клиент; что с ним делать, решает ваше правило.
- **Правила меняются только у вас.** Возможности включить правило извне
  нет и не будет.
- **Матчер один.** Прогон по истории проверяет тот же код, что работает
  на горячем пути, — не его перевод в запрос к базе.
